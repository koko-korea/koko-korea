# 문법의 숲 PRD 분석 및 개발 방향 제안

> 대상 문서: [PRD.md](PRD.md) (v1.0, 2026-11-17)
> 작성: 2026-11-17

## 1. 선행 확인 사항

1. **시제품 `index.html` 미확보**: PRD는 약 280KB 단일 파일 시제품을 전제로 한다("디자인 유지" 항목 다수). 시제품이 있으면 리팩터링, 없으면 처음부터 구현이므로 작업량이 크게 다르다.
2. **기존 앱(저장소 루트, PRD v1.1 「국어 개념 퀴즈 챌린지」)과 설계가 정반대**다.

| | 국어 개념 퀴즈 챌린지 (루트 PRD v1.1) | 문법의 숲 (이 문서) |
|---|---|---|
| 저장 | 서버 + SQLite (→ Supabase 예정) | 저장 없음 (메모리만) |
| 참여 | 익명 닉네임 | 학번 + 이름 + 캐릭터 |
| 출제 | 라운드 방식 | 문제당 1분, 오답 시 즉시 동형(0.5점) |
| 연결 | 서버 API | PeerJS(WebRTC) 직접 연결 |
| 화면 | Next.js + Tailwind | WebGL 3D, 단일 파일 배포 |

→ 기존 코드 개조보다 별도 앱으로 구현하는 편이 낫다(단답형 정규화·CSV 유틸 정도만 재사용).

## 2. 강점

- 화면·점수·대사·색까지 구체적이고, 수용 기준 10개가 테스트로 옮기기 쉽다.
- 결정 기록(12절)이 있어 재질문 비용이 적다.
- "저장하지 않음" 원칙이 명확해 학교 개인정보 측면에서 유리하다.

## 3. 빈틈과 위험 (우선순위 순)

1. **실시간 연결이 최대 불확실성**: 공개 PeerJS 신호 서버 + STUN만으로는 학교 방화벽·대칭형 NAT에서 실패할 수 있다(TURN 없음). UI보다 먼저 학교 와이파이에서 최소 시제품으로 시험한다. `live.js`를 `connect / send / onMessage` 추상화로 감싸 Firebase RTDB 등으로 교체 가능하게 만든다.
2. **새로고침 재응시 (정책 미정)**: 교사 측이 `done`이 아니라 **`join` 시점에 학번을 잠그고**, 교사 화면에 "재입장 허용" 버튼을 둔다. 학생 화면엔 `beforeunload` 경고.
3. **교사 화면 새로고침 = 반 전체 기록 소실**: 교사 화면에도 `beforeunload` 경고, 학생 기기의 재연결·결과 재전송 흐름 정의.
4. **동점 기준 "풀이 시간" 정의 없음**: 해설 읽는 시간을 포함하면 해설을 건너뛴 학생이 유리하다. "문제 표시 ~ 제출 시간의 합(동형 포함)"으로 명시 제안.
5. **단답형 채점 규칙 불일치**: 3.3 규칙으로는 "가획의 원리"가 "가획"으로 정규화되지 않는다. 문항별 인정 답 배열로 명시하고 NFC 정규화를 한다. 옛한글(ㆍ, ㅿ, ㆆ)이 정답인 단답형은 크롬북 입력이 어려우므로 선다형 전환 또는 "아래아" 등 이름도 인정.
6. **보안 (수업용으로 감수 가능 수준)**: 6자리 코드 + 고정 형식 peer id라 `done` 위조가 가능하다. 점수 범위 제한에 더해 동일 학번 중복 접속 거부, 교사의 학생 내보내기 기능 정도면 충분하다.
7. **문제 은행 검토 지연(3.4)**: 정답의 정확성이 가장 중요한 품질이다. CSV 내보내기를 첫 작업으로 해서 개발과 병행 검토.
8. 기타: 글자 크기 `pt` → `px/rem`, PeerJS·qrcodejs를 CDN 대신 번들에 포함(오프라인 요구 충족), 크롬북 WebGL 성능 조기 측정.

## 4. 개발 방향

**기술 스택**: Vite + TypeScript(프레임워크 없음), `vite-plugin-singlefile`로 단일 `index.html` 산출, Vitest(로직) + Playwright(브라우저 2개로 실시간 E2E), GitHub Pages 배포. 폴더 구조는 PRD 10절을 따른다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 | 시제품 확보, 프로젝트 설정, `bank` 분리 + CSV 내보내기 | 교사 문제 검토 시작 |
| 1 | 연결 스파이크: PeerJS 최소 시제품 → 학교 와이파이 시험 | 연결 방식 확정 |
| 2 | `quiz` 엔진: 출제·섞기·채점·타이머·점수·순위 (순수 함수) | 수용 기준 2·3·4 단위 테스트 |
| 3 | `live` + 교사 화면 (재입장 정책·새로고침 대비) | 기준 1·7·9, 2-브라우저 E2E |
| 4 | 화면: 로그인 → 문제 → 동형 → 결과, 대사 시스템, 2D 대체 | 기준 5·6·10 |
| 5 | 3D·캐릭터·순위 발표 연출·효과음·자동 화질 | 기준 8, 크롬북 프레임 측정 |
| 6 | 실기기 점검, 접근성, 배포 | 수업 리허설 1회 |

원칙: **위험한 것(연결)과 정확해야 하는 것(문제·채점)을 먼저, 꾸미는 것(3D)은 나중에.**
